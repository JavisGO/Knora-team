# 用例库：批量异步任务类功能

适用：“上传一批用例 → 创建任务 → 异步多轮执行 → 看列表/详情/统计 → 重跑”这一类功能（批量评测、批量导入、批量处理等）。用例来自一次真实测试的沉淀，已去掉所有环境与对象特定信息。使用时把方括号里的名词换成你的功能，并按需求原文调整预期。

优先级：P0 主链路；P1 规则与校验；P2 体验。数据包名对应 `python -m wft pack` 生成的异常包（见 manifest）。

## A. 入口与配置

| 编号 | 优先级 | 测试项 | 预期 | 数据 |
|---|---|---|---|---|
| A-01 | P1 | 卡片/菜单入口 | 入口存在，文案与需求一致；折叠菜单里的入口要展开确认（标签页在前台） | — |
| A-02 | P1 | 编辑/配置页入口 | 需求要求处存在入口；文案一致 | — |
| A-03 | P1 | 任务列表字段 | 与需求字段逐一核对，无遗漏、顺序合理 | — |
| A-04 | P1 | 新建：默认名称与可改 | 默认名称自动生成，可编辑 | — |
| A-05 | P1 | 任务名称必填 | 清空后提交有明确提示，且未创建 | — |
| A-06 | P2 | 描述选填 | 留空可提交 | — |
| A-07 | P1 | 版本字段 | 按需求带入当前版本；对象无版本概念时记录“需求未明确” | — |
| A-08 | P1 | 轮次/数量边界 | 取值 min、max、min−1、max+1、负数、小数、空：越界应提示并阻止，不得静默改值 | — |

## C. 执行与统计

| 编号 | 优先级 | 测试项 | 预期 | 数据 |
|---|---|---|---|---|
| C-01 | P0 | 主链路冒烟 | 1 用例 × 1 轮创建并跑完 | good 1 行 |
| C-02 | P0 | 总数 = 用例数 × 轮次 | 如 3×3=9，进度按 9 计 | good 3 行 |
| C-03 | P0 | 每条记录带用例序号与轮次 | 逐行核对 | 同上 |
| C-04 | P1 | 状态流转 | 待执行/执行中/成功/失败；尽量捕捉中间态，抓不到写“未捕捉到” | 大规模包 |
| C-05 | P0 | 关闭详情/面板不中断 | 创建后立即关闭，15 秒后重开，进度推进或已完成 | 3×5 |
| C-06 | P0 | 各轮独立（隔离） | “暗号法”：A 告知暗号、B 追问；单用例多轮追问；逐轮记录输出原文 | 暗号包 |
| C-07 | P1 | 结束态定义 | 含失败项的任务结束后的状态与需求一致 | 失败包 |
| C-08 | P1 | 汇总 = 各行之和 | Token/次数等用 eval 求和对比 | C-02 的任务 |
| C-09 | P1 | 总耗时与单次耗时 | 分别计算，并发时可不同 | 同上 |
| C-10 | P1 | “—”与“未获取”与 0 | 待执行显示“—”，无用量显示“未获取”，不以 0 替代 | 需要中间态/无用量 |
| C-11 | P1 | 失败项的用量计入汇总 | 需要失败数据 | 失败包 |

> 造失败数据的常用手段：无效附件（A_bad_file）、超长文本（A_long_text）。如果这些都成功了，就如实写“未能构造失败项”，并向用户/开发询问“如何让被测对象确定失败”（例如临时让某个节点报错）。

## F. 重跑

| 编号 | 优先级 | 测试项 | 预期 |
|---|---|---|---|
| F-01 | P0 | 重新运行全部 | 生成新任务；原任务保留；记录来源任务；记录数与原任务一致 |
| F-02 | P0 | 重新运行失败项 | 只含失败记录；保留原用例序号与轮次；来源正确；沿用原输入与配置 |

## G. 不测或谨慎测

| 项 | 做法 |
|---|---|
| 快照隔离（修改被测对象后看历史） | 会改共享配置，默认标“未测（避免影响共享环境）”；用户明确授权并有可回滚方案才做 |
| 删除、停止、导出 | 不在需求范围就不测，写在“未覆盖项” |
| 他人任务 | 任何情况都不操作 |
